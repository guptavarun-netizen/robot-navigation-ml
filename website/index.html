01 / QUESTION & CLAIM

Accuracy is a beginning.
Reliability is the question.

Autonomous mobile robots make movement decisions from sensors that can be noisy, incomplete, or costly to obtain. A classifier that performs well on clean data may fail when those readings change.

This study asks: how do classical classifiers compare on UCI wall-following sensor snapshots, and how does their class-balanced performance change under noise, per-reading dropout, and fewer available sensor channels?

↳

Useful answer: compare a majority-class baseline with five candidate methods on shared data, inspect per-class errors, and stress the fitted models under repeated simulated sensor corruption. A high classification score alone does not establish successful, safe goal navigation.

!
Odometry timing needs care.

The raw stream contains sub-millisecond intervals. The cleaning script filters each original adjacent interval to 10–100 ms, then recomputes intervals after row removal; 111 resulting intervals exceed 100 ms. Position-derived speeds include implausible spikes, so they are not interpreted as robot speed ground truth. Recorded velocity values are used for the command comparison.

08 / LIMITS & MODEL DISCUSSION

What this evidence
cannot yet tell us.

01 / VALIDATION

Random rows may overstate transfer

The UCI split is stratified by row, but UCI provides no run IDs. Neighboring observations may share conditions, so the test score cannot prove performance on a new robot run.

Improve it:

Collect multiple independent runs and keep each complete run in one held-out fold. The BARN map-ID split adds environment-level evidence, but only in simulation.

02 / SENSOR ROBUSTNESS

Corruption is not hardware failure

Ten seeded noise/dropout repeats perturb the same held-out observations. They show sensitivity to these software masks, not failure behavior in the sensor, wiring, or driver.

Improve it:

Evaluate more independent recordings and realistic fault modes; compare software masks with supervised physical fault trials and report the condition and safety controls.

03 / TASK SCOPE

Action accuracy is not route success

UCI predicts wall-following actions. It does not provide goal-conditioned route demonstrations. The separate navigation policies use synthetic examples, so their simulation outcomes do not validate the UCI classifiers as route planners.

Improve it:

Collect goal-labeled robot trajectories, then report held-out goal completion, collisions, travel time, and path efficiency alongside action metrics.

09 / NEXT MODEL EXPERIMENTS

More reliable evidence.
Stronger models.

These are proposed experiments, not measured improvements. Compare each change on the same held-out data and report macro-F1, accuracy, and per-class recall.

DATA COVERAGE

Collect independent runs

Gather more robot sessions across routes, speeds, surfaces, and sensor conditions. Group train/test splits by run to measure generalization and reduce near-duplicate leakage.

May improve robustness; gains must be measured.
RARE ACTIONS

Target weak classes

Compare class-weighted training and balanced sampling for the less common movement labels. Track macro-F1 and per-class recall so gains on rare actions are visible.

Check that common-class performance does not regress.
MODEL SELECTION

Tune inside cross-validation

Search model parameters using training-only cross-validation, then score the untouched test set once. This can find better settings without turning the test set into a tuning target.

Compare against the current fixed-parameter run.
SENSOR CONTEXT

Test short time windows

Evaluate whether recent sensor readings and motion history help disambiguate actions. Only build windows within known runs and keep entire runs together during validation.

Requires sequential data with reliable run IDs.
